# Importing Arena artifacts — PRISM 0.2.0

PRISM now reads explicit Arena `ArtifactStore` schema-v1 snapshot directories.
Each directory must contain `manifest.json` and `files/`. This is not yet an
importer for entire runs, telemetry exports, mutable package generations, or the
outer demonstration `manifest.json`. Supply the individual content-addressed
artifact directory, normally `.../artifacts/sha256/<prefix>/<artifact-id>/`.

From `prism/` with `PYTHONPATH=src`:

```powershell
python -m prism import-arena --run-id pilot-001 --artifact "C:/path/to/artifact-directory"
```

Repeat `--artifact` for more snapshots from the same run (up to 128). The command
emits a dataset manifest as JSON to stdout; errors go to stderr with exit code 1
and no dataset output. Exit code 0 means all requested artifacts verified. Redirect
stdout to a new file outside the source artifacts if you want to retain the report.
Use the Python adapter with separate explicit run IDs for cross-run datasets.

## Verification

- Validate the manifest version/shape and reject duplicate JSON keys/nonfinite JSON.
- Recalculate Arena's file-tree digest and content/provenance artifact identity.
- Verify every listed file's size and SHA-256; reject missing or extra files.
- Reject path traversal, ambiguous paths, case-colliding paths, symlinks/reparse
  points, special files and linked ancestors.
- Bound manifest bytes (2 MB), file bytes (8 MB), total file bytes (64 MB), and
  directory/file entries (4096) per artifact.

PRISM reads files as data and never executes imported programs. It does not write
to the evidence tree. Run it on quiescent, frozen snapshots: these checks are not
a race-proof sandbox against a separate process changing files during import.
Recomputed hashes establish internal consistency, not producer authenticity. An
attacker able to rewrite both data and manifests can produce a new valid artifact.
Use separately trusted expected hashes when provenance authentication matters.

## Dataset identity and interpretation

The output records entity/version IDs, verified evidence locations and digests,
original provenance as canonical JSON, adapter/PRISM versions and a dataset hash.
Entity IDs encode the caller's run ID and source lineage ID as a JSON pair, avoiding
accidental collision of common lineage names. The caller must use distinct run IDs
for distinct runs. A duplicate entity/version in one dataset is rejected.

The dataset hash covers the manifest body excluding its own hash. Record order is
normalized. Locations are absolute and included in the hash, so relocation creates
a different dataset manifest even when Arena content identities stay unchanged.
No import timestamp is injected, allowing repeated imports to reproduce the same
manifest while source bytes, locations and software version are unchanged.

Preserved `parent_generation` numbers do not reliably identify parent artifacts,
especially in older per-attempt runs. PRISM leaves `parent_version_id` unset rather
than guessing links. It similarly does not infer hidden suite identity, causal
origin labels, comparable resource conditions or scientific metrics from a snapshot.
